## What milestone 11 shipped

- [PR 182](https://github.com/devsandip/the-library/pull/182) (#179): the API reads the token's `sub` as the reader and refuses a request without one (401). Each reader's services are built on their first request and kept while the Lambda is warm, 20 readers at most. A source check carries its reader to the jobs Lambda.
- [PR 183](https://github.com/devsandip/the-library/pull/183) (#180): `CONFIG/OWNER` names the reader whose Gmail the poller reads and whom the scheduled jobs serve; ingest builds its store for the owner at the start of each run, settling runs for the owner. `pnpm name-owner` writes it (on prod from the one Cognito account; on dev from `--id`). Not `pnpm owner`, which is a built-in npm command.
- #181 ("reader" instead of "sandip" in stored moves) moved to milestone 13: the data move there copies every item, so it rewrites the value in one place.

Nothing changed for Sandip: keys carry the reader from milestone 13.
